# Playback and media ownership

SDK **1.2.0** adds `MediaSource.withPlayback(item, original, block)` as an in-process lease over `MediaPlayback(contentUri, cacheKey)`. Extension RPC `media` and its permission/profile validation remain unchanged. No remote HTTP address, auth header or credential is exported. Home/floating route independently; All forwards to the owning member. Native insertion and uploads remain host/source responsibilities respectively; upload bytes are unchanged.

## Progressive reads

SAO's `ProviderMediaDataSource` opens `ContentResolver.openTypedAssetFileDescriptor(uri, "*/*", options, CancellationSignal)` with `MediaStreamOptions.STREAMING=true` and the requested byte `POSITION`. Remote providers return an `AssetFileDescriptor` backed by `StorageManager.openProxyFileDescriptor`. The descriptor has its real full length and proxies absolute offsets, rather than downloading to a temporary file or skipping a pipe to simulate seeking. Local Sticker forwards its existing granted SAF/MediaStore descriptor. Rays forwards its source content URI.

Extensions retain one HTTP response for sequential reads. A changed offset opens `Range: bytes=<offset>-` with `Accept-Encoding: identity` and, when available, a strong ETag/Last-Modified `If-Range`. The shared runtime validates 206 `Content-Range`, actual length, offset and validator. Proxy reads fill the requested block or fail, as Android requires. A valid capped 206 response continues from its declared end when more bytes are actually requested, checking the same validator; unexpected EOF within that segment still fails. This handles partial fulfillment permitted by [RFC 9110 §15.3.7](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.7), without retrying a failed segment. A server ignoring a nonzero range cannot return mismatched bytes. If initial size is unavailable, the provider falls back to its existing cancellable sequential pipe; uncached seeking then remains unavailable. There is no whole-file spool/retry to conceal absent range support. HTTP pools and transport selection stay source-owned.

A per-open `IMediaReadControl` Binder in descriptor extras aborts outstanding reads. It accepts cancellation only from the opening UID. `CancellationSignal` covers opening, but Android detaches its remote after open returns; it alone cannot cancel a subsequent blocked read. SAO cancels this control before closing the descriptor. The extension cancels the HTTP call, closes its response, releases the shared three-reader permit and joins its callback thread. These resources exist only while a descriptor is open, with no polling or idle worker.

Official contracts: [proxy descriptors](https://developer.android.com/reference/android/os/storage/StorageManager#openProxyFileDescriptor(int,android.os.ProxyFileDescriptorCallback,android.os.Handler)), [callback read semantics](https://developer.android.com/reference/android/os/ProxyFileDescriptorCallback#onRead(long,int,byte[])), [Media3 byte caching](https://developer.android.com/media/media3/exoplayer/network-stacks#caching_media).

## Host cache and decoding

One lazily initialized Media3 `SimpleCache`/LRU stores **64 MiB** of bytes actually requested, in 2 MiB fragments. Completed preview/original-file caching is reduced to **128 MiB**, retaining the previous combined 192 MiB budget. Keys bind media revision/rendition to its opaque owning source. Repeated seeks/loops and the large viewer reuse cached spans. Removing a source clears its playback keys even if this process had not opened playback yet. No query results or credentials are cached here.

ExoPlayer reads the cache/provider directly, with decoder fallback enabled, 1–5 seconds/8 MiB loading and no automatic load retries. Muted carousel playback disables audio; the large viewer requests original bytes and standard controls/audio. Hardware reads have their own cancellable lifetime, stopped before player release so blocked provider IO cannot stall a transition to software decoding. Only codec/unsupported-container errors select FFmpeg, never IO/auth failures.

FFmpeg `DecoderInput` callbacks read/seek through the same Media3 cache. It does not reopen a completed source-media file. This is still CPU software decoding; the fallback surface is muted and lacks a Media3 control timeline. Existing local-file native conversion/export APIs remain available. Explicit exports needing a file can create a request-owned snapshot through the same byte cache; its temporary file is deleted after the lease.

## GIF conversion

As GIF is a single host preference across sources/apps and is disabled for stills. It affects explicit Paste, including accessibility clipboard preparation; selecting/toggling does not recopy or encode. Copy and attachment fallback preserve their existing semantics. An unsupported original-native route does not silently turn this preference on. Existing GIF bytes are reused; other animations use gifski with palette, motion and lossy-LZW quality 90. CLI and decoder features remain disabled. All source timestamps are supplied; temporal denoising/frame merging can occur at this quality. Instagram native stickers continue direct frame-to-WebP conversion.

Shared conversion-input selection first tries the original platform decoder, then a compatible source rendition only if neither rotation-corrected dimension exceeds the original, then original software decoding. Unknown geometry or non-square pixels retain the original instead of guessing. Upscaled source playback copies are never conversion inputs. GIF and native-input export identities were advanced so previously cached upscaled/quality-100 conversions are not reused. Uploads and ordinary original-media exports are unaffected.

On an uncached GIF Paste only, cheap local metadata estimates indexed-frame work (`width × height × approximate frames`). At 32 MiB of frame data the UI warns before encoding, showing dimensions/frame count without presenting raw work bytes as a file-size estimate. Missing metadata produces no invented estimate. Actual application limits (such as Discord) are checked against the exported file through the existing explicit smaller-copy/original choice. The GIF preset is fixed at 90; no automatic resizing or target-size quality search is applied.

Prepared native inputs are reused by revision before reopening the source or probing codecs. Packed RGBA uses one bulk copy during native WebP preparation; padded output retains row handling. Encoding CPU cost is otherwise unchanged. No phone latency or final-file size claim is derived from emulator timings.

## Verification

Synthetic emulator fixtures exercise actual proxy descriptors: distant forward/back seeks without fetching a 32 MiB file, exact bytes, malformed/ignored-range rejection, Binder cancellation of blocked reads and permit/resource cleanup. Host checks exercise byte-cache reuse, JNI stream decoding with odd-width MPEG-4, full-size original still/GIF/MP4 loading, an interactive Media3 seek, retained animated-thumbnail callback ownership, and Back preserving home identity/focus without a new search, plus light/dark M3 GIF action states. Separate conversion checks cover exact existing-GIF passthrough and avoiding repeated native-input source reads. The isolated native probe never sends messages; minified module checks run under a foreign UID/class loader and verify both file and stream JNI inputs, resources and shaders.
