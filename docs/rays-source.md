# Rays as an installed-app source

Install the Rays build containing the paged external API changes, then choose **Add source → Rays** in SAO's Media sources page or floating picker. Rays appears in the add menu only while its app is installed and enabled. Existing saved connections remain removable if the app is later uninstalled. Release and development Rays builds can be configured separately and given any source name.

In Rays, enable **Settings → API (Experimental) → API grant**, add SAO's displayed package name (`one.njk.sao`, or `one.njk.sao.testing` for prerelease), and enable its switch. Return to SAO, test the connection, then save. Stock Rays 2.3 does not contain the binding/API fixes; SAO explains that an updated Rays build is needed.

SAO reads only the installed app's public AIDL contract and granted content URIs. Rays retains its database, annotation workflow and models; none are bundled into SAO. Images, GIFs and animated WebP use the existing carousel and copy/paste delivery paths. SVG is rasterized locally for preview and static export. The companion Rays build also imports MP4/WebM originals, shows video thumbnails, and supports manual titles/tags. SAO plays those files with its existing Media3 player. Image-only ML suggestions remain unchanged for photos and skip videos.

Search passes the complete Unicode query to Rays, including emoji. Matching follows Rays' title/tag search domains, regex and whitespace settings. Immich's context/people/place controls, chronology browsing and random-search buttons are not exposed for Rays. Queries are not cached by this provider. The existing in-memory picker session can retain the current result set while reopening the picker, and prepared clipboard exports retain their existing file cache.

Each page requests at most 60 items and advances using Rays' explicit next offset until the end. The Binder connection exists only for a request, all blocking IPC and content reads run on IO, and switching sources cancels stale work. Binding times out after five seconds; failures require an explicit retry and never start an automatic retry loop. Video playback keeps a bounded, 128 MiB local cache (64 MiB per file); images remain in Rays until the user invokes an export action. SAO validates URI authority and source identity before opening it.

Validation uses Android 15 with a separate installed Rays build, a 65-item synthetic library, and four explicitly authorized local sticker/video copies kept outside both repositories. It covers paging to EOF, page-scoped URI grants, Unicode queries, GIF/animated-WebP byte preservation, static WebP sticker export, SVG rasterization, MP4/WebM playback files, H.264 conversion and source switching. The companion Rays fork includes standalone API tests and client-contract documentation.

WebM delivery retains the original when the target supports it. When a native bridge or the selected sharing receiver rejects WebM at capability checking but accepts MP4, SAO exports H.264/AAC MP4 through Media3 Transformer before its single handoff. Conversion controls and callbacks use a temporary HandlerThread; codecs and file IO run off the main thread, and cancellation removes partial output and releases the worker. An ambiguous send result is never automatically retried. Exported MP4 is a normal attachment, with no video transparency or sticker guarantee.
