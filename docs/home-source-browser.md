# Home and source collections

Tap the **Collection** heading to select an installed source profile, or hold and drag vertically to preview looping choices and release to switch. This reuses the floating picker's selector and configured hold delay (160 ms initially), with the full tap list and accessibility actions retained. Only source profiles appear in the gesture list. Use the pencil to manage sources. Category chips come from that extension, including its preset query and supported search mode. Install **Immich 1.1.0** or **Local Sticker 1.4.1** for presets, filenames and the current import UI. Existing profiles/credentials remain in their extension.

The 450 dp carousel, Material chips and bottom bookmark/download/share actions remain. A centered Material Hero strategy reserves two narrow 32 dp previews around the prominent card; at the start/end Material shifts the previews to the available side. Home reuses the floating picker's media adapter and focal-keyline controller: focused GIFs animate, one muted Media3 player previews the focused video, and actions use the actual focal card. Playback stops when hidden. The current result set, category and focus live in the ViewModel/SavedStateHandle, with no scroll/query preference writes. New indexing notifications refresh visible browsing without resetting focus or retrying a failed read.

The carousel mounts immediately, with the original `eager.webp` sticker inside each card while its image loads. There is no separate loading text or sticker overlay. After a metadata page arrives, SAO warms a moving window of at most four nearby display previews, with at most two speculative transfers. It follows the settled scrolling direction and pauses while scrolling or hidden. Preview bytes use the existing shared media cache and transfer deduplication; original-file fallbacks are skipped. A failed speculative request pauses warming for that browse. No search-result cache or background polling is added. The source switches under **Show in floating picker** do not restrict the main screen. Main and floating sessions have separate routing/cancellation, with the same shared media cache and per-output export coordination.

[Light/dark home previews](screenshots/README.md#home-source-collections). The original README images remain the layout reference.

Source-loading errors offer **Retry** and **Source settings** directly in the carousel. Settings opens the failing profile's extension-owned form without changing the main or floating selection. **All** instead offers **Media sources**, since it combines multiple profiles. Returning without edits preserves the failed browse; Retry reloads the same collection only when pressed.

## Custom home categories

Open **Settings → Home categories → Edit**, choose a source profile, then add, edit or remove its chips. The inline editor accepts an optional label, a supported search mode and a query. When the extension advertises suggestions, typing two characters offers its own completions; Moeview supplies board-specific tags. Picking a suggestion preserves the other query terms. Blank labels use the query text. **Reset to source defaults** restores the extension's presets; removing every category intentionally leaves no chips.

This page belongs in SAO's main settings because categories control its home presentation. Extension forms continue to own credentials and domain configuration; the source-management list stays focused on profiles and floating visibility. Choosing a profile here does not switch the browsing source. Overrides are keyed by stable host profile ID, survive renaming/reconfiguration and are removed when the profile is deleted. Only Save, Remove and Reset persist changes; drafts stay in the ViewModel. Floating search and provider defaults are unaffected. Label-only edits update home chips without refetching media or losing carousel focus.

The shared carousel uses Material's placement/scrolling without RecyclerView item-change fades. This avoids a reproduced detached-holder crash when keyboard resizing switches strategies during a search-result update. [Category editor and completion previews](screenshots/README.md#search-suggestions-and-home-categories).

## Experimental All source

Enable **Settings → Media sources → All sources (experimental)**, then select **All** from either browser. Disabling it while selected returns to a real source. Only installed profiles participate. Credentials, authentication and provider APIs remain in their source APKs.

Each host page reads at most three provider pages with at most three concurrent requests, rotating fairly through profiles. New results are shuffled together; appending pages keeps already displayed cards in place. This is page-wise mixing, not a uniform random sample of every file in every library. Each provider keeps its own opaque continuation. Asset identity includes the owning profile, so equal asset IDs in different accounts remain distinct, and previews/originals/video/sequence requests route to the right owner. Configuration/membership changes invalidate the composite session and cancel its work. Exhausted providers stop receiving requests; repeated/cycling cursors stop pagination. Cursor history stores pagination metadata, not previous-query results.

All advertises common search modes and supported facets; People/Places are disabled because their IDs belong to a particular account. Context remains the default when common, otherwise Description is preferred when available. Preset categories are collected from the members. Random and sequence controls are offered when every member supports them.

A failed provider does not discard successful results or advance that provider's cursor. An inline message pauses automatic fetching until **Retry**. Retry resumes unfinished positions; completed providers are not fetched again. Local indexing notifications cannot restart a failed aggregate request. Existing bounded read retries still apply inside the ordinary extension adapter; there is no idle polling/reconnect loop or disk query cache.

## Sharing, filenames and original quality

Home **Share** sends the displayed image, GIF or video using its existing host-cached rendition. It does not request the separate original. Share snapshots use the host export store with bounded retention and handoff/clipboard protection; see the [export policy](media-exports.md). Preview bytes are preserved without recompression, and the MIME/extension match the actual preview format (for example, a JPEG preview of a PNG original). GIFs stay animated and videos use the playback file. **Download** alone requests the original on the home screen.

Hold the **media title** in home or the floating picker to copy its original filename. Image holds retain chronological browsing. Both use the configured hold delay, initially 160 ms. Copying a filename supersedes any pending image-copy job; both publications share the clipboard dispatcher and ordering guard. Filename is a separate extension field: an edited description is never substituted for it. Older providers without filenames cannot offer this action.

**Download** and floating **Media** copy/share preserve the original file's bytes, MIME type, resolution and transparency. Ordinary static photos no longer pass through a 512×512 JPEG canvas or receive white padding. Sticker exports keep their dedicated 512-pixel conversion. A new export namespace prevents reuse of earlier reduced-quality files. Synthetic tests cover the reported filename shape, a 3000×1800 JPEG, transparent PNGs, provider streams, title-hold copying and the Telegram Media clipboard path; no personal library is accessed. A receiving app can still apply its own compression.
