# Host UI motion

SAO uses Views and its existing Material dependency. Extension APIs are unchanged.

- Settings and Usage are Fragment destinations inside MainActivity. Navigation's four animation options are resolved at runtime from the platform `android.R.style.Animation_Activity` attributes, matching AndroidX's documented `TRANSIT_FRAGMENT_MATCH_ACTIVITY_OPEN/CLOSE` behavior. No copied animation files, app-defined duration/distance, additional Activities or cross-Activity screen-state cache are used. Edit retains its existing Activity route. These are platform resource animations inside one window; they do not claim to reproduce every OEM window-manager or predictive-Back effect.
- `ui/SaoMotion.kt` owns small control visibility effects only: native LayoutTransition appearing/disappearing animations, zero start delay, and no changing-layout or ancestor animations. Logical visibility/input update immediately, and lifecycle stop restores prior transitions.
- The picker search field, source/target and inline options panels open and close through those visibility effects. Long-press selectors retire their drawing in an overlay for 90 ms while applying the selection immediately. The picker is a separate task: Android owns cross-task entrance/exit motion. Finish and floating-icon ownership release are immediate; no fade delay is inserted. The card freezes its geometry against late keyboard-hide updates during exit.
- `floating/PickerWindowMotion.kt` synchronizes the card with WindowInsetsAnimationCompat progress. Destination geometry is measured once; frame callbacks update View bounds and outline without measuring or laying out carousel children. Interrupted animations settle, and strategy changes wait for IME completion. Dismissal freezes the card drawing against late IME-hide layouts; loading reserves its progress-track space to keep carousel geometry stable.
- Carousel strategy changes retain the same manager and focused asset. Material 1.14 initializes strategy defaults only on attachment; replacement Hero strategies therefore receive the library's public size dimensions explicitly. LayoutAwareCarouselSnapHelper defers snapping while keylines are invalidated for layout.
- Source labels use native wrap-content measurement, a maximum width, end ellipsis and a 48 dp minimum height. Header width changes update that limit after layout; there is no source-text bounds animation.
- Explicit source/mode/filter changes are immediate; only text edits are debounced. A source change uses the current text even while its typing debounce is pending. Changed sources or unsupported modes cancel old result requests while waiting for matching capabilities. During capability loading, existing control space stays stable and unavailable controls are disabled.
- Android animation settings are respected. No polling, background workers, preference writes or new dependencies were added. Ordinary media binding and carousel scrolling do not trigger effects.

Usage-specific value/calendar effects remain in `usage/UsageMotion.kt`, scoped by section. They present final prepared values and never change recorded counts. See [usage analytics](usage-analytics.md) for aggregation and lifecycle caching.

## Validation

Targeted device checks cover navigation/recreation, retained reports across popping, unaffected section reuse, month browsing, future-date drawing/accessibility, keyboard intermediate geometry, retained carousel manager/focus, immediate dismissal, source selection, filter state and chronology. Rendering is checked with recordings/frame traces on an isolated API 35 emulator and synthetic media, rather than only checking settled screens. Debug-emulator timings are diagnostic, not a benchmark of every physical device. Artifacts are local under `/srv/samba/share/tmp/analytics/responsive/` and `/srv/samba/share/tmp/sao-motion/responsive/`.

Android documents cross-task animation overrides as unavailable from Android 11; see [Activity transition API documentation](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r36/core/java/android/app/Activity.java#L6872). Custom window animation resources were removed because they do not control that task transition.
